Option A - Two-mode single window

The same GM window has an explicit setup mode and review mode. Sending the prompt removes the editable form entirely, replaces it with a compact read-only summary, and moves players directly beside the live preview.

Pros

  • Lowest false-editable risk after Send because the form disappears.
  • Best players-to-preview proximity without adding another window.
  • Keeps reload and ownership behavior centered on one manager app.

Cons

  • Requires a real stage switch in render state and template structure.
  • GM cannot inspect every setup detail at full size unless the summary expands elsewhere.
  • Mode transition needs careful state preservation for draft prompts.

Option B - Stronger disabled styling

This keeps the current single-view layout after Send, but makes the setup fieldsets unmistakably locked with desaturation, reduced opacity, lock chips in each legend, disabled controls, and a diagonal scrim.

Pros

  • Smallest code change and least disruption to the current template.
  • GMs can still see all setup details at a glance.
  • Strong lock treatment directly addresses the false-editable complaint.

Cons

  • Players and preview remain pushed below the setup fieldsets.
  • The locked form still consumes attention during review.
  • Heavy disabled styling can feel visually noisy in a compact Foundry window.

Option C - Collapsed summary accordion

After Send, setup collapses into compact read-only accordion bars. The GM can expand a summary when needed, while the players list and preview still move up into the primary review area.

Pros

  • Balances review focus with access to setup details.
  • Significantly improves players-to-preview proximity.
  • Scales if more setup fields are added later.

Cons

  • More component states than Option B and less decisive than Option A.
  • Expanded accordions can reintroduce vertical push.
  • Needs clear affordance so GMs understand summaries are read-only.

Option D - Two separate windows

Setup and review become distinct windows: a compact "New Drawing Prompt" composer and a focused "Prompt Review" monitor. This is clean conceptually, but has known costs in window juggling and ambiguity about which window should reopen after a reload.

Pros

  • Each window has one job and can be sized for that job.
  • Review window gives players and preview maximum room.
  • Setup can close after Send without implying active fields remain editable.

Cons

  • More window management for GMs during live play.
  • Reload behavior needs policy: reopen setup, review, or both?
  • More app lifecycle code, placement persistence, and user preference surface.
