# Canvas plate, display stage, and surface-specific chrome

Display UI is three cases, not one shared “fullscreen chrome canvas.” The **Canvas plate** is always the aspect-true proxy for Prompt canvas (or source-aspect box for Source Framing review). Rejected: forcing Canvas chrome only on the player plate (that would leave pan/zoom padding looking like “not background” and fight stage-wide chrome). Rejected: giving GM Assignment review full player navigation/engine (review is static dual Framing Views). Rejected: letting outer stage chrome imply drawable Submission space without a **Plate border**.

**Player workstation:** Chrome fills the **Display stage**; plate keeps W×H aspect and carries Framed background + ink; thin Plate border; open/reset = fit plate in stage; tools hit plate only.

**GM compose framing:** Chrome only on the plate; plate is the framing pan/zoom surface; exterior is plain panel void; aspect = draft Prompt canvas dims; resizes with the pane.

**GM Assignment review:** Static image(s) only (no pan/zoom, no draw engine). Prompt-canvas Framing View seeds from live/pending, then saved, then Framed background—not an empty “no snapshot” state when delivery exists. Source Framing is separate source-space imagery. Efficient responsive `<img>` (or equivalent), with Plate border style consolidated with existing preview edges so frames do not stack.
